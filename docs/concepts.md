# Concepts

这份文档是项目的“随工程增长的词典”。概念第一次用到时先给直觉，再给工程含义。

## Git 仓库

Git 仓库是带版本历史的项目目录。它记录文件在每次提交中的状态，让实验代码、参数和结论可以回溯。Git 是本地版本管理工具；GitHub 是可托管 Git 仓库的远端平台，两者不是同一个东西。

## Python 虚拟环境

虚拟环境是项目专属的 Python 与依赖安装空间。本项目使用 `.venv`，从而避免 MuJoCo、NumPy 等包与系统 Python 或其他项目互相影响。进入项目后用 `source .venv/bin/activate` 激活，终端提示符通常会出现 `(.venv)`。

## 仿真模型

仿真模型是对真实系统的有目的简化。它不是越复杂越好；好的模型只保留当前问题所需的结构、质量、惯量、约束、驱动和接触。我们先用单关节，是为了隔离最基础的运动与控制关系。

## MuJoCo

MuJoCo 是面向关节系统、接触和控制的物理仿真引擎。它能根据模型、当前状态和输入力矩推进时间，得到下一时刻的位置与速度。相较大型机器人平台，它安装更轻、运行更快，适合先建立动力学与控制直觉。

## Body（刚体）

Body 表示具有位置、姿态、质量和惯量的刚体，例如大腿、小腿或外骨骼连杆。多个 body 通过 joint 形成机械系统。

## Joint（关节）

Joint 约束两个刚体之间允许怎样运动。膝关节的第一版可近似为只允许绕一个轴旋转的 hinge joint。真实膝关节更复杂，但简化模型更适合先学习控制。

## Degree of Freedom（自由度，DoF）

自由度是描述系统独立运动所需的变量数量。单个 hinge joint 有一个自由度，可用一个角度描述。三个独立旋转关节通常有三个自由度。

## Position 与 Velocity

Position 描述关节当前“在哪里”，旋转关节通常用弧度表示角度。Velocity 描述位置变化有多快，旋转关节常用弧度/秒。控制器会读取二者作为反馈。

## Torque（力矩）

力矩可以直觉地理解为“让物体绕轴旋转的作用”。同样大小的直线力，作用点离转轴越远，产生的力矩通常越大。在外骨骼中，人体肌肉和电机可以共同对关节提供力矩。

## Actuator（执行器）

Actuator 把控制命令转成模型中的力或力矩。MuJoCo 的 motor actuator 可直接对关节施加与控制输入相关的力矩，可作为第一版外骨骼电机的抽象。

## Phase 1 模型如何对应真实系统

`models/single_joint/single_joint.xml` 中的元素可以这样理解：

| MuJoCo 元素 | 当前模型 | 真实系统类比 |
| --- | --- | --- |
| `world` | 不运动的参考坐标系和地面 | 房间/实验台 |
| `base` body | 固定在 world 上的蓝色基座 | 外骨骼大腿侧的固定端或测试架 |
| `link` body | 长 0.5 m、质量 1 kg 的橙色杆 | 小腿或外骨骼连杆 |
| `hinge` joint | 绕 Y 轴旋转，角度有限位 | 简化的膝关节 |
| `joint_motor` actuator | 最大正负 2 N·m，`gear=1` | 关节电机及减速器的简化表示 |

这里的 base 没有 joint，所以 MuJoCo 会把它固定到 world；link 通过一个 hinge 连接到 base，因此整个模型只有一个自由度。

## qpos、qvel 与 ctrl

MuJoCo 把系统状态放在数组中：

- `data.qpos`：广义位置；在当前单 hinge 模型中，第一个值就是关节角度，单位 rad。
- `data.qvel`：广义速度；当前模型中是关节角速度，单位 rad/s。
- `data.ctrl`：发给 actuator 的控制输入；当前 motor 的 `gear=1`，所以输入 `0.5` 表示施加约 `0.5 N·m` 的关节力矩。

真实复杂模型中，数组会包含许多关节，因此代码先通过关节/执行器名称找到地址，而不假设它永远位于索引 0。

## Open-loop Torque（开环力矩）

Phase 1 的实验从开始到结束一直发送同一个力矩。它不根据当前角度或速度修改命令，因此叫开环控制。开环能证明“输入力矩会改变运动状态”，但不能保证关节准确到达某个目标角度；这正是 Phase 2 引入反馈和 PD 控制的原因。

## Feedback Control（反馈控制）

反馈控制不断读取当前状态，与目标状态比较，再根据误差更新控制输入。它不是只发一次命令，而是形成“测量 → 比较 → 调整”的循环。

## PD Control（先用人话理解）

是的，PD 就是 PID 里的 P 和 D：

- **P 看现在差多少**：离目标越远，电机推得越用力。
- **I 记住过去一直差多少**：如果长时间到不了目标，它会一点点追加力矩。
- **D 看现在动得多快**：快冲过头时提前“踩刹车”。

Phase 2 暂时不用 I，有两个原因。第一，先只学“拉向目标”和“抑制冲过头”，比较容易看懂。第二，电机有 `±2 N·m` 上限；如果长期到不了目标，I 会一直累加，松开后可能突然冲出去，这叫积分饱和。机器人关节常先用 **PD + 重力补偿**，知道还差多少重力就直接补多少；以后再学习带防积分饱和的 PID。

PD 控制器由位置误差项和速度误差项组成：

```text
torque = Kp × position_error + Kd × velocity_error
```

其中：

```text
position_error = target_position - current_position
velocity_error = target_velocity - current_velocity
```

`Kp` 可以想成弹簧的硬度：软弹簧必须拉开很远才有足够大的力，硬弹簧只需拉开一点。`Kd` 可以想成缓冲器：运动越快，它越用力阻止关节继续猛冲。

Phase 2 的程序在每个 `0.002 s` 物理时间步执行一次闭环：

```text
读取 qpos/qvel → 计算误差 → PD 计算 → 限幅 → 写入 ctrl → MuJoCo 推进一步
```

## Torque Saturation（力矩饱和/限幅）

当前执行器只能输出 `[-2, 2] N·m`。例如目标 30°、`Kp=30`，初始位置误差约 `0.524 rad`，仅 P 项就要求约 `15.7 N·m`，远超电机能力；程序会把实际 `ctrl` 截到 `2 N·m`。响应图中的 `raw PD` 是控制器原本想要的力矩，`applied` 才是模型实际收到的力矩。限幅让仿真更接近真实电机，也能暴露“参数很大不等于动作无限快”。

## 为什么有误差还不够？

关键不是“有没有误差”，而是“这点误差产生的力矩够不够”。例如 `Kp=5 N·m/rad`，换算成角度后，每差 `1°` 只能产生约 `0.087 N·m`。目标为 `-45°` 时：

- 如果只差 `1°`，电机只有约 `0.087 N·m`，托不住杆，杆还会往回掉。
- 掉到约 `-30.7°` 时，与目标相差约 `14.3°`。
- `14.3 × 0.087 ≈ 1.25 N·m`，这时电机力矩终于和当前位置的重力矩一样大，杆才停住。

这就像用软弹簧吊一个重物：弹簧只拉长一点时力气不够，必须再拉长一些才能托住重物。`Kp` 越大，弹簧越硬，需要的角度误差就越小。

电机限幅只表示“最多能给多大力矩”，不会自动替 PD 补力矩。`-45°` 所需的 `-1.734 N·m` 虽在电机能力内，但纯 PD 到达目标后误差为 0，会命令电机输出 0，所以仍然保持不住。

以后可以用两种办法缩小误差：重力补偿是提前算出“要托住它需要多少力”并直接加上；I 项则是发现长期有误差后慢慢把力补上。
