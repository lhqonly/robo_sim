# Progress Log

## 2026-07-28 — Phase 2.6：控制响应时间与稳定判定

新增按每个 `0.002 s` 物理步运行的阶跃响应分析器，不再依赖网页刷新频率或肉眼估计。每次应用目标/增益、切换重力补偿或重置姿态都会开始一轮新测量；MuJoCo 原生 Reset 导致仿真时间回零时也会自动重新开始。

默认以误差进入 `±1°` 并连续保持 `0.5 s` 作为稳定条件，网页可实时修改并用本轮完整采样重新计算。面板显示已经运行、首次到达、10%～90% 上升时间、稳定时间、确认稳定耗时、最大超调和当前误差；角度曲线新增黄色稳定允许范围。若关节稳定后又振荡出界，分析器会撤销稳定状态并重新计时。

目标 `45°`、`Kp=5`、`Kd=3`、开启重力补偿的 8 秒数值验证结果：上升时间 `1.314 s`，首次进入 `±1°` 为 `2.316 s`，稳定时间 `2.316 s`，在 `2.816 s` 获得连续 `0.5 s` 的确认，最大超调约 `0°`。

说明同步强调这些数值只覆盖当前仿真模型，不包含真实外骨骼的传感器、滤波、通信、电机驱动和人体耦合延迟。

## 2026-07-28 — Phase 2.5：PD + 重力补偿

为保留纯 PD 静态误差这一学习现象，同时继续展示常见机器人关节控制方法，新增可实时开关的重力补偿。它不是 I 项：MuJoCo 先按当前模型和姿态计算需要托住杆的 `qfrc_bias`，控制器再计算 `P + D` 修正角度/速度，两者相加后统一经过电机 `[-2, 2] N·m` 限幅。

中文面板增加“重力补偿”开关和小白说明；状态卡与 30 秒动态力矩曲线拆分显示 PD 力矩、重力补偿力矩和实际总力矩。命令行增加 `--gravity-compensation`，并输出每个采样点的 PD/补偿分项。

相同参数目标 `30°`、`Kp=5`、`Kd=3`、仿真 8 秒的对照结果：

- 纯 PD：最终 `20.266°`，误差 `9.734°`，PD 输出约 `0.849 N·m`。
- PD + 重力补偿：最终 `30.000°`，误差约 `0.000°`；PD 接近 `0 N·m`，补偿约 `1.226 N·m`。

自动化测试覆盖前馈力矩必须在执行器限幅前与 PD 相加、网页开关 API，以及纯 PD/补偿模式的最终误差对照。

## 2026-07-10 — Phase 2：实时响应曲线与静态误差解释

用户在目标 `-45°`、`Kp=5`、`Kd=3` 时观察到关节只到约 `-30°`，且电机并未限幅。数值复核表明目标保持力矩约为 `-1.734 N·m`，理论纯 PD 平衡点约 `-30.67°`；10 秒仿真得到约 `-30.74°`。平衡点处 P 项约 `-1.24 N·m`，与当前位置重力/偏置矩约 `-1.25 N·m` 抵消，确认根因是纯 PD 在重力下的静态误差，而不是限幅或目标输入失效。

中文面板新增最近 30 秒的实时角度、角速度和力矩三联曲线；角度图同时记录动态目标与实际值，力矩图区分 raw PD、applied 和 `±2 N·m` 限幅。新增实时平衡解释卡，展示目标保持力矩、当前位置偏置矩、P/D 分项，并直接说明为何停在当前角度。修复了 DOM 区域 ID 标错及 `[hidden]` 样式优先级导致 PD 模式仍出现恒扭矩输入区的问题，同时保证 Watch 区始终显示。

曲线复验还发现原模型的橙色杆持续与蓝色基座、黄色电机外壳发生自碰撞，并在约 7 秒产生非控制器导致的速度尖峰。两者只是视觉教学几何体，现已禁止参与碰撞；复验接触数从持续多接触降为 0，3 秒后的最大角速度从约 `40 deg/s` 降至 `0.053 deg/s`，10 秒结果平滑收敛到理论平衡点 `-30.666°`。

## 2026-07-10 — Phase 1：单关节与恒力矩实验

### 目标

用最小模型建立 `body → joint → actuator → state` 的可运行链路，观察力矩如何改变关节位置和速度；本阶段不引入反馈控制。

### 实现

## 2026-07-10 — 修复不完整虚拟环境

### 现象

运行 `source .venv/bin/activate` 报告文件不存在。随后执行的 `python` 实际来自 `/opt/rk-toolchain/bin/python`，因缺少 `libpython2.7.so.1.0` 失败；`pytest` 则来自用户级全局安装，而不是项目环境。

### 根因与修复

当前 Ubuntu 缺少 `python3.12-venv` 的 `ensurepip` 组件。`python3 -m venv` 在生成激活脚本之前失败，但留下了 Python 软链接，旧版 setup 脚本因此把半成品误判为完整环境。现在 setup 脚本会显式检查 `bin/activate`，缺失时用 `venv --without-pip` 补齐脚本，再定向引导 pip；修复后仍缺失则立即报错。

### 验证

在新的 Bash shell 中激活成功，`python` 和 `pytest` 均指向 `/home/lhq24/robo_sim/.venv/bin/`；环境检查通过，pytest 结果为 `2 passed`。
